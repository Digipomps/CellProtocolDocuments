## Én utstedelsesinngang, én policy, én lagringssti

- **Inngang:** `ManagedArtistImportCoordinator` → `ScaffoldMandateCell.consumeArtistImport` → fileprivate `ManagedArtistIssuanceVault.issue(consumed:seedDigest:tokenHash:)`. Mandatet må være signert, gyldig og ubrukt idet det forbrukes. Ingen generell utstedelsesrett via resolver eller vault-protokoll oppstår.
- **Policy:** `managedArtistImport` / `managed-artist-import.consumed-mandate`, klassifisert som `separateIssuanceVault` + `ownerApprovedIssuance` + `externalVaultOnly`. De eksisterende policytypene passet; ingen CellProtocol-kjerneutvidelse var nødvendig.
- **Lagring:** `CELL_VAULT_DOCUMENT_ROOT/DigipompsManagedArtistIssuance/vault.crypt`. En egen 32-byte `MANAGED_ARTIST_ISSUANCE_KEY_B64` må provisjoneres av drift. Ingen fallback til sentralhvelvet, brukerhvelv eller automatisk nøkkelgenerering for krypteringen.
- Katalog 0700, filer 0600, ingen fulgte symlinker, ingen hardlinkede filer, eksklusiv prosesslease, autentisert AES-GCM-snapshot, fsync/rename/readback, avvisning ved uventet lagringsendring. Root må være eksplisitt og kanonisk.
- Den forvaltede signeringsnøkkelen kan bare brukes under selve importfasen. Ved avsluttet overtakelse eller fjerning slettes den fra gjeldende krypterte snapshot. Metadata-lesinger returnerer aldri nøkkelmaterialet.
- Sentralhvelvets configure/strict-kode, manifestskriver og provisjoner er uendret. Registerets inventarantall, kildeevidens og digest-golden er oppdatert fordi den pålagte policyen/siten er lagt til; ingen strict-denial-assertion er svekket eller fjernet.

## Celler og API

Alle nye operasjoner er på `cell:///ScaffoldMandate`, med vanlig requester-/signaturkontroll. Ingen ny generell ImportCell eller HTTP-login er lagt til.

| Keypath | Payload / effekt |
|---|---|
| `mandate.issue` | Eksisterende utstedelse med ny type `artistImport`. Krever nåværende, eier-signert representantmyndighet. Signert scope omfatter kunstner, samtykke, én bruk, 24 timer og bare `artistImport.execute`. |
| `artistImport.execute` | `{mandateID, seed, previews, claimToken}`. `previews` er workID → `{dataBase64, mimeType}`; ingen serversti/URL lastes fra seed. Token er 32 klientgenererte tilfeldige bytes i base64url. |
| `artistImport.claim` | `{mandateID, claimToken, rightsOwnershipAttested: true, contentPolicyAttested: true}`. Requester er en eksisterende ekstern identitet med `BridgeIdentityVault`. Ukjente felter, herunder private-key-felter, avvises. |
| `artistImport.removeAll` | `{mandateID, reason}` fra den beviste kunstneren eller gjeldende administratorrepresentant. Varig tombstone blokkerer katalog, sider, verk og direkte previews. |
| `artistImport.status` | `{mandateID}`. Bare bevist importør, kunstner eller administrator. Kvitteringen inneholder kun importID, phase og artistSlug. |

`IdentitySigningChallenge.proveControl` brukes for lokale aktører. BridgeIdentityVaults standardmetoder beviser ikke lokal vault-medlemskap, så ekstern kontroll bruker samme strukturerte `IdentitySigningChallenge.signingData` + offentlig signaturverifisering som eksisterende `GeneralCell.checkIdentityOrigin`. En frisk challenge bindes til import-ID, seed-digest, tokenhash og eksplisitt rettighets-/innholdsbekreftelse. BrowserClientIdentityVault brukes ikke for overtakelsen.

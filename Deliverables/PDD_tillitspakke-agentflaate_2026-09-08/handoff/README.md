3. Hver kodeendring refererer sin `purposeRef` i commit-melding/kommentar. Ingen `git` gjennom mount; ingen `git push`. Commit lokalt er ok.
4. Ikke fjern eller svekk eksisterende tester. Ikke dokumenter planlagt oppførsel som implementert.
5. Hemmeligheter: aldri i kode, fixtures, logger eller TESTRESULT. Ingen `.env`-lesing utover det testene trenger; bruk fixture-stores.
6. Skriv ekte testutdata (ikke sammendrag) under ankeret i `P/TESTRESULT.md`. En test som ikke kunne kjøres er `blocked` + grunn.
7. Oppdater `P/STATUS.md` med én linje: dato, WP, resultat, eventuelle avvik. Skriv sluttmeldingen din til leveransestien (linje 3 i .job), ikke til `_svar.md`.
8. Formål gir aldri rettigheter. Ukjent feiler lukket. Pakken kan bare innsnevre.
9. **SwiftPM i Codex-sandkassen:** bruk alltid `swift build --disable-sandbox` og `swift test --disable-sandbox` (også med `--filter`). SwiftPMs egen `sandbox-exec` kan ikke nestes i Codex-sandkassen og gir `sandbox_apply: Operation not permitted` (sett i WP0 08.09 og i alle jobber 07.09). Ikke bruk tid på å diagnostisere det på nytt.
10. **Bygg og test — oppskriften som virker i Codex-sandkassen (målt WP0b/WP0c 08.09):** bygg med `swift build --disable-sandbox --build-tests` **uten** `arch`-prefiks (med `arch -arm64` foran feiler manifestfasen på nektet skrivetilgang til Clangs modulcache). Kjør tester **direkte** med `xcrun --sdk macosx xctest <repo>/.build/arm64-apple-macosx/debug/<Pakke>PackageTests.xctest` (CellProtocol: `CellProtocolPackageTests.xctest`; CellScaffold: `CellsContainerPackageTests.xctest`) — det laster arm64 riktig; `swift test` velger x86_64-lasteren og feiler med `incompatible architecture`. Én testklasse: `xcrun --sdk macosx xctest -XCTest <Modul>.<TestKlasse> <bundle>`. Full CellScaffold-kjøring tar ~15 min. Swift Testing-mål dekkes ikke av denne veien; si det i TESTRESULT hvis relevant.
11. **Aldri bytt gren tilbake mens senere slicer trenger arbeidstreet.** Post 0 (08.09, 01:28) committet WP2–WP7 til `pdd/tillitspakke-agentflaate` i CellScaffold og gjorde deretter `git checkout` tilbake til originalgrenen — koden forsvant fra arbeidstreet, og WP8, WP9 og WP10 kjørte 0 tester («blocked») i 40 minutter. Sjekk alltid at koden slicen din bygger på faktisk finnes i arbeidstreet (`ls` på en nøkkelfil) **før** du bygger — er den borte, stopp og si fra i stedet for å rapportere grønt bygg med 0 tester. **Forhåndssjekken skal navngi filer, aldri telle dem** — 09.09 06:00 blokkerte «mappen skal vise 6 filer» både WP11, WP12 og WP13 fordi WP10 hadde lagt til en syvende fil.

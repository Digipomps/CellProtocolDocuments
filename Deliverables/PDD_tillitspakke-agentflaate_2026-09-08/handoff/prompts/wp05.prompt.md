WP5, purposeRef `purpose://candidate.tillitspakke-agentflaate.webfetch-ceiling`:
1. `CellScaffold/Sources/App/Cells/WebKnowledge/WebKnowledgeCells.swift` (`WebFetchCell`): ny `WebFetchCeiling: Codable` (schema `haven.webfetch-ceiling.v0`: `hostPatterns: [String]`, `methods: ["GET"]`, `https: true`, `allowCredentials: false`, `followRedirects: false`, `maxBytes`). Lagres som **data per celle-instans** (eier-scopet, persistent — bruk cellens eksisterende persistens/EntityAnchor-mønster; keypath `webFetch.ceiling` GET (r---) og `webFetch.ceiling.set` SET (rw--, kun eier)). Ingen ceiling lagret = **deny all** (fail closed), med typed grunn `ceiling_missing`.
2. Håndheving i `web.fetch`, **før** nettverk, i denne rekkefølgen: scheme (`https_required`) → metode (`method_not_allowed`; kun GET, ingen body) → vert mot mønstre (`host_not_whitelisted`; regler: `*.x` matcher subdomener av x, ikke x selv; eksakt vert bare seg selv; port må matche om oppgitt i mønster, ellers bare 443; case-insensitiv; ingen wildcard midt i navn) → credential-alias i request (`credential_not_granted` når `allowCredentials=false` eller requester mangler Grant til `ScopedCredential`; 0 oppslag skal skje) → utfør med `followRedirects: false`; ved 3xx: `Location` sjekkes mot mønstrene, utenfor → `denied(redirect_outside_whitelist)` uten ny request. Deny-svar er typed (`status: denied`, `reason`, ingen rå URL-innhold utover vert), ikke throw som skjuler grunnen.
3. `AgentTrustPackageCell` leser `webFetch.ceiling` og viser `ceilingLabel` («kun GET · https · whitelist: … · credentials: NEI») og `hostPatterns` i pakken (WP2 hadde «ingen whitelist ennå»-fallback — erstatt den).
4. Tester i `CellScaffold/Tests/AppTests/WebFetchCeilingTests.swift`, med injisert URL-protokoll/mock som **teller** faktiske requests: (a) tabelltest fra `neg-whitelist-cases.json` (alle 11 rader, forventet reason); (b) 302 fra whitelistet vert til ikke-whitelistet → 1 request, ikke 2, `redirect_outside_whitelist`; (c) credential-alias uten rett → 0 oppslag i ScopedCredential (fixture-store teller); (d) manglende ceiling → deny all; (e) tillatt fetch fungerer og respekterer `maxBytes`; (f) ceiling kan ikke settes av annen requester enn eier.
5. Bygg/test etter regel 10; kjør `-XCTest AppTests.WebFetchCeilingTests`, deretter **hele bundlen** (~15 min; baseline 2046/46 røde → nå forventet 2059+ med samme røde navn, ingen nye).

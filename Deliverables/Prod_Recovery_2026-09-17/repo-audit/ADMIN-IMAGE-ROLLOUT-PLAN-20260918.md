## Staging: exact existing procedure and its limits

The runbook's literal sequence is `scripts/deploy-admin-staging.sh plan`, then `deploy`, `verify`, `status`; explicit rollback is `scripts/deploy-admin-staging.sh rollback`. Execute only after reconciling the actual existing container/Compose project/storage with the script's contract. [Runbook sequence](/private/tmp/haven-prod-20260917/CellScaffold/Documentation/AdminScaffold_M4_Runbook.md:146)

Required release inputs are `ADMIN_SCAFFOLD_IMAGE`, `NODE_ADMIN_TOOLS_IMAGE` as digest refs and `ADMIN_SCAFFOLD_EXPECTED_COMMIT` as full SHA. The checkout must be clean at that exact commit. The script enforces `https://admin.staging.haven.digipomps.org`, port 8083, storage `/mnt/disk1/admin/CellsContainer`, existing owner UUID/fingerprint, private key-file paths, monitoring/alerting/synthetic-check values, and staging node-agent identity/ingest configuration. Merely overriding variables cannot turn this into a production script. [Paths/defaults](/private/tmp/haven-prod-20260917/CellScaffold/scripts/deploy-admin-staging.sh:26), [hard gates](/private/tmp/haven-prod-20260917/CellScaffold/scripts/deploy-admin-staging.sh:232), [node-agent environment](/private/tmp/haven-prod-20260917/CellScaffold/scripts/deploy-admin-staging.sh:101)

These are historical paths to verify, not assumed current values. The script allows explicit Compose directory/file/env paths. It does not specify a project name, so existing Compose project identity must be retained to avoid creating a second service. [Isolated Compose evidence](/private/tmp/haven-prod-20260917/CellScaffold/Documentation/Operations/Staging_Admin_Deploy_2026-08-09.md:94)

**Plan is not read-only:** image validation logs into GHCR using a token file and pulls both images. The staging script has no capacity gate before that pull. `deploy` also copies runtime materials, installs node tools and host monitoring/nginx/backup configuration, enables timers and reloads nginx; it is broader than a container-only image swap. It then performs Compose `up -d --no-build --no-deps admin-scaffold`. The current recovery coordination excludes a broad installer shortcut, so a coordinator must reconcile this mismatch before invoking it. [Pull behavior](/private/tmp/haven-prod-20260917/CellScaffold/scripts/deploy-admin-staging.sh:135), [deploy mutations](/private/tmp/haven-prod-20260917/CellScaffold/scripts/deploy-admin-staging.sh:683)

It does **not** restore a previous storage generation. `deploy` writes new state before verification and has no automatic rollback trap for failed verification. Confirm the previous recorded pair is genuine before cutover; retain quiesced backup/restore evidence separately. Never bootstrap a new owner over existing storage. ## Dependency on the admin mandate integration

`ScaffoldAdministratorRegistryCell`, `ScaffoldMandateCell`, proof support, provisioner and readiness support are under `Sources/App`; `Sources/Run/main.swift` owns provision-only mode and `Sources/App/configure.swift` reconciles those cells. `Run` depends on App. **AdminScaffold depends only on ScaffoldKit**, starts `configureAdminScaffold`, and its 13 persisted infrastructure cells do not include ScaffoldMandate or ScaffoldAdministratorRegistry. `Dockerfile.admin` builds only AdminScaffold and AdminScaffoldBootstrap. [Target split](/private/tmp/haven-prod-20260917/CellScaffold/Package.swift:258), [admin entrypoint](/private/tmp/haven-prod-20260917/CellScaffold/Sources/AdminScaffold/main.swift:4), [admin cell descriptors](/private/tmp/haven-prod-20260917/CellScaffold/Sources/ScaffoldKit/AdminScaffoldRuntime.swift:409), [image products](/private/tmp/haven-prod-20260917/CellScaffold/Dockerfile.admin:41)

Therefore web/main's new image is required for the integrated mandate feature. Updating AdminScaffold images is **not a prerequisite solely for that feature**, and does not provision any mandate. Web readiness explicitly tolerates both new authority cells being absent as a safe unprovisioned state, while partial/corrupt mappings fail closed. Preserve that behavior and the recovery instruction not to run an administrator provisioner as part of image deployment. Shared CP/ScaffoldKit improvements can still justify the separate admin upgrade and require compatibility testing against the old persisted infrastructure state. [Unprovisioned readiness behavior](/private/tmp/haven-prod-20260917/CellScaffold/Sources/App/Support/ScaffoldAdministratorRuntimeSupport.swift:23)

### Current owner/vault model and migration risk

Protected actions are registry owner mutation, representative mandate/org-link issuance/revocation, and the opted-in target's apply/reset. Registry text or web admin role is not authority. The representative needs an exact owner-signed Contract scoped to the current registration-receipt domain. Target use rechecks mandate state and revocation. No new service/provider identity is required by this feature.

Both new Cells install bindings with `PaymentGateOwnerIdentitySupport.requireSigningIdentity(for: storedOwnerIdentity)`. The candidate implementation rehydrates only matching UUID/key fingerprint and expected home vault, then proves signing control. There is no new `makeNewIfNotFound: true` owner fallback. The one-shot representative lookup first requires the existing Fido record's `identityId`; `BrowserClientIdentityVault.identity(for: user)` then takes `resolvePersistedWebIdentity`, which rejects missing signing material and conflicting context rather than provisioning a replacement identity. It may persist canonical metadata/healed key descriptors through the existing guarded vault implementation.

These new cells must use the existing scaffold owner domain (`ownerContext`) and exact canonical mappings. Do not overwrite candidate `configure.swift`, owner support, BrowserClient/Vapor vaults, or authenticated Admin bridge with complete older files. The proposed six commits do not themselves replace those key/vault/bridge classes. Existing mapping recovery and sealed-credential changes must survive conflict resolution.

**Deployment stop condition if importing only the committed branch:** committed readiness makes a require-existing deployment with no admin mappings unavailable. The dirty `ScaffoldAdministratorRuntimeSupport.swift` deliberately treats both registry and mandate absent as degraded-ready/no authority, while one present or a corrupt pair remains unavailable. This fix and `testRequireExistingAcceptsAbsentPairButRejectsPartialMapping` are mandatory together with startup integration. Provision-if-missing ordinary development startup can create the empty pair; require-existing production startup must not.

The new persisted registry validates references, threshold and reason. The mandate decoder rejects malformed persisted record shapes; both rely on normal GeneralCell decoding and owner restoration. Evidence does not establish migration/restart success yet. Run missing-pair, partial-pair, corrupt-owner/key, valid-existing-pair and cold-restart tests before activation. A partial pair is a readiness blocker by design; do not silently create its missing counterpart in production.

### Concrete remaining defects and limitations

1. **Requester status in the unattached-reference fallback is wrong.** Dirty `AdminWorkspaceConfigurationFactory` adds a `scaffoldAdministrator` reference to `ScaffoldMandate.representative.status`. Normal already-attached references preserve the actual user. However, fallback inspection in `PortholeWebSessionSupport.bootstrapValueInRequestScope` resolves scaffold-unique references through the scaffold owner. Its `attachedReferenceRequester` has no exception for this requester-private status and passes that lookup identity into the projection. The later requester projection only redacts denied fields; a successful status is not replaced. Consequently the fallback can show the owner's status instead of the logged-in representative's. Add an explicit real-requester path for the mandate status and a bootstrap regression covering distinct owner, authorized user and stranger. This is conditional on the fallback, not a claim that every load is wrong.
2. **Absent admin pair produces a blank status UI.** The intended safe no-mapping deployment leaves the endpoint unregistered. Bootstrap returns `connected=false` and no status fields, while the new panel binds plain labels. No process crash was established by source inspection. Provide a clear unavailable/not-provisioned display or omit the panel until a status source is available. Verify the entire Product Administration workspace still loads.
3. **Staging script rollback remains armed after deleting its backup.** After verified restarts the final helper writes its receipt and deletes `cells.tar` and checksum, then the script prints its final line. `SERVICE_STOPPED`, `MUTATION_ATTEMPTED` and `BACKUP_READY` are never cleared. A failing final output/helper after deletion enters the exit trap, stops the healthy container and attempts restore from missing backup. Add a committed latch/disarm rollback before destroying rollback material; test failures at receipt creation, backup cleanup and final output. This is a stop bug for executing the operator script, not for merely shipping its disabled source.
4. **Malformed stored representative authority is conflated with absence.** `ScaffoldAdministratorProvisioner` reads existing authority with `try?`; malformed or unreadable existing proof takes the nil/new-grant path. A parsed but expired/wrong Contract is correctly rejected. Distinguish proven absence from decode/storage failure so the explicit provisioning operation does not silently replace damaged authority evidence. Test malformed stored proof and storage denial without mutation.
5. **The direct one-shot stdin path is unbounded before validation.** `Run/main.swift` uses `readDataToEndOfFile`; the 32 KiB check occurs afterwards. The wrapper checks request file size, but a direct invocation bypasses that memory bound. Read at most limit+1 before decoding. This is local operator input, not an exposed HTTP listener.
6. The operations README says the request file is deleted. The script only removes its temporary directory and never deletes the caller-supplied request. Correct that retention statement or make an explicit bounded cleanup decision; do not delete user source/request data by inference.

One-shot mode is deliberately restricted to exact staging `VAPOR_ENV`, RP ID and RP origin and requires provision-only/provision-if-missing flags. Keep it disabled during normal image deployment. Its script stops the named service, backs up/restores the storage volume, and installs four 90-day rights; it is not part of deploying Butler. The historical staging approval text in the worktree is evidence of design scope, not a fresh instruction to mutate prod authority. No script or grant operation was attempted here.

Required admin verification: registry suite (8 methods), mandate suite (9 methods including positive/negative/threshold fixtures), role suite (role denial matrix plus source guard), provisioner suite (2 methods) and admin factory tests. Add tests for the listed UI fallback and damaged proof, and run unchanged existing Arendalsuka credential tests if taking the optional extraction call-site refactor. ## `ec437501`: independent signed-caller bridge

This commit adds a general inbound `VaporCellBridge` plus registration in `routes.swift`. It is not necessary to execute the existing Butler web path: `POST /browserhead/porthole/action` uses the authenticated local Porthole session and `PortholeWebSessionSupport.executeAction`; configured chat references target `cell:///PersonalChatHub`, whose identity-unique resolver is registered by `configure.swift`. First-use provisioning also resolves that local endpoint. Existing authenticated Admin bridge traffic uses a separate implementation.

Keep this package separate until its handshake proof contract is repaired and tested. `shouldUpgrade` verifies/consumes the signing challenge nonce via `provenCaller`; the WebSocket handler calls the same verifier again, which rejects the already-consumed nonce. Verification needs to be performed once and its exact authenticated caller passed safely into the upgrade handler. The verified caller is visibly logged but bridge configuration/resolver registration uses `publisherIdentity`; trace the actual CP bridge principal binding and test it, rather than asserting authentication alone establishes per-operation authority. No new tests accompany the branch.

The dirty outbound `RemoteBridgeheadAccess` host/bearer support is not automatically its compatible other half: this inbound package accepts signed caller/Sprout proof forms, not that bearer token. Test the actual native/remote consumer protocol, forged and replayed proof, wrong domain/resource, unauthenticated caller, connection success, and denied Meddle/Absorb after a successful handshake. Only then can this separate network feature claim an operational cross-scaffold path.

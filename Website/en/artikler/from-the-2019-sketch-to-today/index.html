From the 2019 sketch to today

HAVEN was first described as “a global platform” with eight services. We withdraw that. Here is what lives on, in what form, and what we no longer claim.

The first public description of HAVEN, from 2019, sat at /tjenester/ until September 2026. It called HAVEN “a global digital platform”, said the platform “maximises value” and “solves the weaknesses of today’s solutions”, and set the goal of becoming the platform “the whole digital world” uses. It also described eight named services: Gate, Vault, Sprawl, Mind, Buzz, Bazaar, Proxy and Ledger.

Those phrases contradict what we say elsewhere on this site. The status page says we do not claim global scale or societal effect. The front page says “We promise less than we can show.” So the address has been retired and the claims withdrawn. This page stands in its place, so that it is possible to see where the idea came from and what became of it.

What lives on

Most of what the 2019 sketch set out to solve, we are still working on. But it goes by other names now, it is bounded differently, and it is labelled with what actually exists.

2019 sketchToday
Gate – authentication and linking of IDsIdentity is scoped to each domain. Linking across domains happens only with a proof the owner has given. Implemented in the core, tested in bounded parts.
Vault – consent and contractsAn agreement that becomes a contract, with a declared purpose, bounded rights and conditions. Implemented in the core.
Sprawl and Mind – profile data and storage formatEntity data under the owner’s control, with cells as the only way in. Base model implemented; the user journey is not ready for a public pilot.
Proxy – anonymity through translated IDsBuilt into the domain scoping itself. There is no global ID to translate from.
Ledger – secure log for value transferA specified event format for where value ends up, which can be simulated. Not deployed. Not a blockchain.
Buzz – messages between profilesCorrespondence, in pilot.
Bazaar – normalised objectsPartly covered by a shared vocabulary with labels in several languages. The rest is open.
“Global platform”, “critical mass”, “the whole digital world”Withdrawn. HAVEN is open rules and components others can build on. Scale is neither documented nor a goal in itself.

What did not come along

The idea that one steward would gather “the most and richest user data” in one place is gone. It contradicts what is now the first rule: a service is designed to ask for as little as possible. The idea that value is “maximised” by sharing as much as possible is gone too. What we examine instead is whether a service can give more back to the individual and to the commons when it is built on declared purpose, minimal data, receipts and the ability to revoke. That is a hypothesis we want tested by others, not something we have shown.

What still stands is the rationale: that data the owner can carry along can create value more than once (value networks, Stabell and Fjeldstad 1998), and that the rights to move one’s own data and to be forgotten are things we build for, not around.

Basis and limits

This comparison is based on the 2019 text as it stood at /tjenester/ until 7 September 2026, on the status page (last reviewed 1 August 2026) and on the project’s internal claims canon. The maturity labels in the table are the same as on the status page. The correction is recorded in the corrections log. The contradiction was found by an external read-through on 7 September 2026.
